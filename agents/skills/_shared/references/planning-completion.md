# Planning Completion Handoff

After feature or story planning is reviewed, accepted and validated, offer to run
`/jr-commit` for those planning changes as the single next action, before proposing
implementation or unrelated follow-ups. Name the scope: the feature/story specification
and its related planning updates. Do not commit merely because a planning contract
or the resulting specification was approved.

An explicit request to commit these changes, or acceptance of this offer, authorizes
the handoff: follow `jr-commit` for scope review, validation, staging and execution
without asking again. Report a commit only after verifying it succeeded. If those
changes are already committed, do not offer an empty or duplicate commit.

Honor an explicit no-commit, hold, or different next action. A declined commit is
not a failed planning workflow; retain the files and accurately report their state.
Keep deferred follow-ups available for after the commit or the user's chosen action.
