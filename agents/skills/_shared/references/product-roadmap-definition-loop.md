# Product and Roadmap Definition Loop (Shared)

Use this shared loop for commands that define or revise product direction.

Profiles:
- `init` profile: use all questions exactly as written.
- `roadmap` profile: use all sections exactly as written.

## Mission

Understand WHAT is being built and WHY. Focus on USER VALUE and SIMPLICITY.

Critical: challenge ideas that do not make sense. It is better to surface concerns early than build the wrong product.

## One-Question Rule (Non-Negotiable)

- Ask ONE focused question at a time.
- Never ask multiple questions in one turn.
- Wait for answer, process it, then ask the next.

Why this matters:
- Deep understanding of each answer.
- Ability to challenge vague responses.
- Natural conversation flow.
- Progressive context building.

## Step 1: Silent Gap Analysis

Before asking any questions, silently identify what is missing:
- What problem matters to people?
- Who experiences this problem?
- What value does this provide?
- What are the essential capabilities (3 max)?
- How will success be measured?
- What constraints exist (time, resources)?
- What risks could prevent success?

Then ask questions to fill these gaps, ONE at a time, targeting highest-impact unknowns first.

## Step 2: Core Product Questions

Challenge vague answers. Push for clarity and simplicity.

1. The Core Problem

"What problem are we solving that matters to people?"

- NOT: "What features will it have?"
- YES: "What frustration or pain point does this eliminate?"
- Push for: specific, relatable, meaningful problem

2. Who Experiences This

"Who has this problem? Be specific."

- NOT: "Everyone" or "Developers"
- YES: "Solo developers who maintain multiple open source projects"
- Push for: concrete persona and real context

3. The Value - Simple

"In one sentence: what's the core value?"

- NOT: features list
- YES: "Lets you do X without Y" or "Makes X as simple as Y"
- Push for: crystal clear value proposition
- Think: could you explain this to your grandparent?

4. Why This Matters

"Why does this matter enough to build?"

- What's the impact if this exists?
- What's the cost if it doesn't?
- Push for: meaningful purpose, not just "nice to have"

5. What Makes It Simple

"What are the 3 essential things it must do? Nothing else."

- NOT: 10 features
- YES: 3 core capabilities that deliver the value
- Push for: ruthless simplicity
- Challenge: "Can we do this with 2 instead of 3?"

6. Success Definition

"How will you know this succeeded?"

- NOT: "People like it"
- YES: "10 people use it daily within a month" or "Reduces X by 50%"
- Push for: measurable, specific outcome

7. Initial Slice Scope (execution profile)

"What is the smallest usable slice we can ship first?"

- Define minimal usable capability
- What is the absolute minimum next sequence that delivers value?
- Optional timebox is allowed, but must not redefine product scope

8. Product Horizon Scope

"What capabilities are intentionally in long-term scope after the initial slice?"

- Capture strategic direction explicitly
- Must be preserved in roadmap unless user removes it

9. What We Are NOT Building

"What are we explicitly NOT doing?"

- What features are OUT?
- What complexity are we avoiding?
- Push for: clear boundaries

## Critical Analysis Responsibility

Challenge and push back when needed:
- Scope too large -> recommend phasing to get to user value faster
- Problem vague -> push for specifics about real people
- Features do not deliver value -> question why they are included
- Success unclear -> push for measurable outcomes
- Complexity creeping in -> challenge: "Can we simplify this?"
- Technical conflicts -> explain implications clearly

Challenge complexity:
- If scope seems large: "Can we cut this in half and still deliver value?"
- If features do not align with value: "How does this feature deliver the core value?"
- If problem is vague: "Give me a specific example of someone experiencing this problem."
- If success is unclear: "What is the ONE metric that matters most?"

## Completion Gate

Continue until 95% confident on: problem, users, value, simplicity, success.

Consistency check (mandatory):
- Never list a declared long-term goal as a product non-goal.
- Non-goals must be tagged as either:
  - "Initial-slice non-goal", or
  - "Product-level exclusion".

Do not proceed to next phases until product direction is crystal clear.
